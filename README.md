# Dr. Blackburn Digital website

Production source for https://www.drblackburndigital.com/ — Dr. Blackburn Digital GmbH i.G.

## Development

Requires Node.js 20 or later. Install from the lockfile and build before running tests:

```sh
npm ci
npm run build
npm run build:preview
npm test
npm run dev
```

The local website is at http://127.0.0.1:4173/. `npm run preview` serves the same content with a visible local-review banner at http://127.0.0.1:4174/. With both servers running, `npm run test:browser` checks responsive layouts, accessibility, language switching and form behaviour. Local and preview environments cannot deliver email.

## Source and deployment

- `src/`: English/German content and legal notices.
- `scripts/build.mjs`: layout, metadata, structured data and static output.
- `assets/`: self-hosted images, styles and contact script.
- `api/contact.js` and `server/`: server-side validation, rate limits and mail delivery.
- `tests/`: site and form regression checks.
- `vercel.json`: build `npm run build`, publish only `dist`, function region Frankfurt (`fra1`).

The root `index.html` is generated by the production build. Edit the sources and rebuild. Never serve the repository root or publish `preview-dist`. Vercel preview deployments are also noindexed, and cannot send mail. Legal pages are intentionally noindexed but remain publicly linked.

GitHub `main` is the production source branch. A push can trigger Vercel production deployment; review and test changes before pushing. Credentials and deployment settings remain in Vercel and are not changed by the build.

Private review material and internal operator records are excluded from this public repository. The company remains in formation; update legal status and registry details only after confirmation.

## Contact delivery

The live form sends plain-text notifications from `website@drblackburndigital.com` to `info@drblackburndigital.com`. The visitor address is used only as Reply-To, never as the sending identity. The approved Workspace account can authenticate an alias/send-as identity; a separate website mailbox is not inherently required. Sending through the approved account was verified end-to-end on 27 September 2026.

`Visitor browser → Vercel function → Google Workspace → info@drblackburndigital.com`

Configure all mail values only in Vercel Production. `.env.example` has deliberately disabled flags and no credentials. Required configuration:

- `NODE_ENV=production`, `NODEJS_HELPERS=0` (raw request body).
- `CONTACT_FORM_ENABLED=true` only after verified configuration and authorised delivery testing.
- `CONTACT_SENDER_VERIFIED=true`, `CONTACT_EMAIL_AUTH_VERIFIED=true`, `CONTACT_LOG_RETENTION_REVIEWED=true` only after completing those checks.
- `GOOGLE_WORKSPACE_USER`: approved account login. The approved primary account fingerprint is an allowlist identifier in the server source; the address itself stays in Vercel.
- `GOOGLE_WORKSPACE_APP_PASSWORD`: dedicated revocable app password, stored as a Sensitive Production variable.
- `CONTACT_RATE_LIMIT_KEY_SECRET`: at least 32 random characters, stored as a Sensitive Production variable.

SMTP uses `smtp.gmail.com:465` with certificate-verified TLS. Keep SPF, aligned DKIM and DMARC working for the sending identity. Retest after changing the account, alias or credentials. Never print SMTP errors or message contents into logs.

The existing Vercel rate-limit rules are required; missing rules fail closed:

| SDK rule ID | Limit | Window | Counting key |
|---|---|---|---|
| `dbd-contact-ip` | 5 | 600 seconds | `header:x-vercel-rate-limit-key` |
| `dbd-contact-global` | 30 | 600 seconds | `header:x-vercel-rate-limit-key` |

Use fixed-window `rate_limit` rules matching the SDK `rate_limit_api_id`. The function supplies a keyed pseudonymous IP value to the first rule and a shared key to the second. Do not substitute IP-based infrastructure counting. The function is restricted to `fra1` for consistent regional enforcement.

The application has no enquiry database, payload logging, browser storage, analytics, tracking or CAPTCHA. Vercel still processes connection metadata. The reviewed runtime-log product has 30-day retention and no log drains; this is not a guarantee for every provider record or backup. Mail enquiries that do not become a business relationship are deleted within six months of correspondence closing, subject to legal retention obligations or an open dispute. See the published Privacy notice for the full current disclosure.

## Verification

Tests cover body/field limits, validation, plain-text rendering, sender/Reply-To separation, Origin/method checks, generic errors, rate-limit failures, deployment gates, navigation, languages and unpublished-output exclusions. Browser tests mock delivery locally and do not send mail. `GET /api/contact/` exposes only the delivery-enabled status; a successful POST means SMTP acceptance. Actual inbox receipt must be confirmed separately for an end-to-end delivery test.
